# 安徽英科医疗导航 · 手机网页

将微信小程序「GLU-Campus-Guide」复刻为可在浏览器中运行的手机版网页单页应用（SPA），
保留地图选点/搜索、路线规划、点位汇总（基地介绍）和厂区简介等功能。

> 已移除「首页」「行程安排」两个 Tab；原首页顶部的厂区 Hero（企业名 / 上市标签 / 基地简介）
> 现置于「基地介绍」页最上方。

## 运行方式

### 方式一：Node 代理服务器（推荐，路线规划可用）
```bash
node server.js
```
然后浏览器打开 `http://localhost:8000`（建议使用手机模式/开发者工具模拟移动端）。

> `server.js` 提供 `/api/weather`、`/api/route` 代理，解决跨域；腾讯方向 API 在额度耗尽时自动降级为估算路线。

### 方式二：任意静态服务器
```bash
cd web-guide
python -m http.server 8000
```
打开 `http://localhost:8000`。此时天气可直连加载；路线会走本地估算兜底。

### 方式三：直接打开
双击 `index.html` 也可查看（地图、天气等大部分功能正常，路线为估算）。

## 页面结构
- 底部 Tab：地图 / 基地介绍（原「青州地图」Tab 已移除，基地切换改由地图页顶部胶囊承担）
- 子页：搜索地点、使用说明、厂区简介、全景地图
- 「基地介绍」页顶部为厂区 Hero（原首页 Hero）
- 基地（淮北 / 青州）为全局状态 `state.campus`：地图页顶部胶囊、基地介绍页右上角、搜索页切换
  三处共用同一索引，任一处切换其余页面同步生效
- 地图页把「丁腈车间 + PVC车间」合并为「生产车间」展示（见 `js/app.js` 的 `MAP_CATEGORY_MERGE`）：
  **只作用于地图侧**，基地介绍页仍按 `data.js` 的原始分类展示，点位弹窗与标记配色仍按各自原分类走
- 搜索子页（`#/search`）：
  - **点结果整行 = 打开该区域的讲解弹窗**，与地图页点标记完全同一个 `openGuideDialog`；
  - 行内「**定位**」按钮 = 以该点位为中心回到「地图讲解」页：先把分类切到该点位所属分类
    （`displayCategoryIndexFor()`，跳过虚拟「全部」，合并分类按来源分类名匹配），
    再由 `applyPendingFocus()` 在 `onMapShow()` 末尾统一 `setView`（`FOCUS_ZOOM = 18`）；
    因为回到地图页可能先要按基地差异重载数据、重绘标记，视角必须最后定；
  - 结果携带来源分类名（`p._catName || 分类名`），所以合并分类里的点位弹窗文案与配色仍按原分类走；
  - 页面图标全部为**内联 SVG**（`SEARCH_SVG`），不依赖任何外链图片；
  - 页体可滚动、标题栏吸顶，底部留出 TabBar 高度。

## 移动端权限（定位 / 方向）
- 定位：进入地图页自动 `getCurrentPosition` + `watchPosition`，蓝点实时跟随。
- 方向（蓝点箭头）：判向数据来自设备传感器，iOS Safari 必须先由**页面内的一次用户手势**
  调用 `DeviceOrientationEvent.requestPermission()`；定位权限弹窗上的「允许」是系统弹窗，
  **不算**页面手势，所以「定位成功后自动申请」在 iOS 上会拿到 `NotAllowedError`。
  `js/app.js` 的 `initOrientation()` 因此分三条路走：
  1. 本地记录（`localStorage['glu.orientation.granted']`）显示此前已授权 → 进入页面即静默申请，直接生效；
  2. 首次进入 → 挂上「页面首次触摸即申请」（`armOrientationGesture`）并弹出底部引导条
     `#mapOrientHint`（轻触屏幕，开启方向指引），用户不必去找右侧的朝向按钮；
  3. 用户明确选「不允许」→ 不再反复打扰，右侧朝向按钮 `forceRetry` 仍可手动重试。
- `NotAllowedError`（缺手势）与 `denied`（用户拒绝）**必须区分**：前者不能置 `mapOrientationPermissionDenied`，
  否则会被自己锁死、后续不再申请。

## 技术栈
- 原生 HTML/CSS/JS（无构建）
- Leaflet + 腾讯地图瓦片（矢量底图，TMS 翻转）
- 地图默认叠加手绘园区示意图 `map_bottom1.png`；右上角“真实地图”可切换为真实底图 + 区域边界多边形
- 浏览器定位（WGS-84）自动转为 GCJ-02 后再标点，消除国内地图坐标偏移
- 腾讯位置服务方向 API（+ 本机代理 + 估算兜底）
- 和风天气 API
- 数据由小程序 `data/map.js | school.js | data.js | media.js` 转换而来（见 `js/data.js`）

目的
1.销售新手能实现地图导航，知道自己的参观路线
2.参观者不能看导航，耳机能够自动有参观讲解


1. **引导员端（发射主机）**
   - 讲解员手持发射机，可以：本地预存多条讲解音频 MP3，也可以讲解员直接麦克风真人说话；一键切换频道 / 讲解内容；播放、暂停、上一曲、下一曲。
   - 两种模式：
   ①真人扩声模式：引导员直接说话，所有游客耳机实时听见人声；
   ②预录音频播放模式：引导员按键，直接播放提前录好的点位录音，游客耳机输出录音。
2. **游客端（入耳耳机接收单元）**
   - 游客只佩戴轻便接收耳机，**没有任何按键，完全不能操作**。只负责收听，不能切换、不能调音量（音量可以锁死）。
   - 形态：挂脖接收器 + 入耳耳塞，整套无操作按键，分发的时候接待人员开机配对好直接给游客戴上。游客不需要做任何动作。
3. 配套：充电收纳柜，参观结束统一回收集中充电。

### 工作流程

1. 接待室：工作人员把所有接收耳机提前和讲解员发射主机配对、音量锁死。
2. 直接给到游客佩戴，游客**全程不触碰任何设备**。
3. 园区参观行进：
   - 到达 1 号点位：引导员在自己的主机，按下播放【点位 1 讲解录音】，所有游客耳机同步播放该音频；
   - 讲解完毕，引导员暂停；走到下一个点位，引导员按键切换到【点位 2 录音】播放；
   - 也可以随时切回真人讲话模式，引导员直接口头补充说明，游客耳机实时听到人声。
4. 参观结束统一收回耳机。

✅优点

1. 完全满足需求：游客不能碰任何设备，全部控制权交给引导员；真人讲解 + 预录音频可随时切换。
2. 不受位置限制，**不需要在点位部署发射器**，不需要布线施工，不需要在园区装 Beacon、UWB 基站。走到任何地方都可以切换音频。
3. 支持多组频道：多批参观团互不干扰，A 团引导员只控制 A 团耳机，B 团互不串音。
4. 音质清晰，抗干扰，适合工厂、产业园、室外园区。

❌局限

- 需要收发设备的分发回收管理，需要充电柜；
- **不是根据位置自动触发**，全部由引导员手动操控，需要引导员记住点位对应的音频序号；

手动采集每个参观点位经纬度，把参观路线拐点坐标全部预先存数据库。
