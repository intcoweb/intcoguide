## marker 几何关键结论（改样式前务必先看）
- 全局 `* { box-sizing: border-box }`。`.campus-marker` 容器 40×46；`.marker-pin` 为方形 + `border-radius:50% 50% 50% 0` + `rotate(-45deg)`，**圆头圆心 = pin 边框盒中心**（旋转绕该点，坐标不变），针尖在圆心正下方 √2·r 处。
- **陷阱：`--pin-*` 只是偏移量，pin 用 `left/top`（相对定位）而不是 margin。** 若给 pin 用 `margin-top`，会与 `.campus-marker`（无 padding/border，非 BFC）发生外边距合并，把整个容器推下去，而绝对定位的光圈不动 → 光圈与 pin 分离。
- **陷阱：绝对定位子元素按"内边距盒"定位。** pin 有 border，所以若在 pin 内放 `::after` 之类绝对定位元素，`left:7px` 实际落在边框盒 9px 处（多出 border 宽度）。白点问题（已按要求删除该圆点）就出在这条规则上，别再凭直觉按边框盒写偏移。
- 现方案：`.campus-marker` 定义 `--pin-size/--pin-left/--pin-top`，pin 与 `.marker-pulse` **共用同一组变量**（光圈 `left/top/width/height` 全取变量），盒子完全重合 → 圆心必然一致；要整体缩放只改三行。当前 `--pin-size:17px`（原 26 的 2/3，小三分之一）、`--pin-left:11.5px`（圆头圆心保持容器 x=20）、`--pin-top:10.9px`（针尖保持 y≈31.4，缩小后点位不位移）。pin 的 border/阴影同比缩小（1.5px / 0 2px 4px / 0 0 0 2px）；`.start` 规则需显式 `left:0;top:0` 抵消变量。
- pin 内的白色小圆点（`.marker-pin::after`）曾按用户要求删除，后又按要求加回。**最终写法：`left:50%; top:50%; width: calc(var(--pin-size)*.3); margin: calc(var(--pin-size)*-.15) 0 0 calc(var(--pin-size)*-.15)`** —— 50% 解析的是内边距盒中心，因 border 上下左右对称，内边距盒中心 == 边框盒中心 == pin 的旋转中心，所以天然同心且随 --pin-size 等比缩放；不要再写死像素（写死就会重犯"圆点偏左 2.83px"的错）。`.campus-marker.start .marker-pin::after`（定位点的小尖角）单独保留。
- 「工厂大门」专用绿色门楼图标（CSS `.campus-marker.gate` + `.gate-symbol*`，JS `gateClass`）**已按要求整体废弃**：工厂大门作为默认起点现按普通点位渲染，与「办公室」完全同款（普通 pin、tone-life 配色、呼吸光圈、label top:30px）。JS 侧 `formMarker` 不再输出 `gate` class；`renderCategoryMarkers` 里 `isDefaultPoint`（name === '工厂大门'）仍传 type='site' + tone='life' + categoryName='生活配套'，以保证标签显示「工厂大门」且可点开弹窗。CSS 里保留一段注释说明该历史，别再把 `.gate` 规则加回来。
- **呼吸光圈"没有效果"的真正原因（重要教训）**：`@media (prefers-reduced-motion: reduce)` 里原本写了 `animation: none`，而光圈基础样式是 `opacity:0` → 在"Windows 辅助功能→视觉效果→动画效果"关闭的机器上，光圈**完全不可见**（不是"没居中"）。现改为：该分支不做位移动画，但保留常驻光环（`::before` 取 `scale(1.45)`）+ `markerGlow` 纯透明度呼吸，保证任何环境下都看得见。
- 另外把 `animation-delay` 全部改成**负延时**（`calc(var(--pulse-delay) - 2.8s / -1.4s)`），避免加载后 1.4~6 秒内光圈还没开始、看起来像"没有效果"。
